## แบบฝึกหัด: ./mvnw dependency:tree

| library / starter | มีไว้ทำอะไร |
|---|---|
| spring-boot-starter-test | starter รวม dependency สำหรับทดสอบไว้ชุดเดียว (JUnit, AssertJ, Mockito, Spring Test ฯลฯ) และเป็นตัวเดียวที่เราประกาศเองใน pom.xml ที่เหลือใน tree เป็น transitive dependency |
| junit-jupiter | test framework หลัก ให้ annotation เช่น @Test และ engine ที่ค้นหา/รัน test แล้วรายงานผล pass/fail |
| assertj-core | assertion library แบบ fluent เช่น assertThat(x).isEqualTo(y) อ่านง่ายและ error message ละเอียดกว่า assertEquals |
| mockito-core | สร้าง mock/stub แทน dependency จริง เพื่อทดสอบ class หนึ่งโดยแยกออกจากส่วนอื่น (เช่น repository, service ภายนอก) |
| spring-test / spring-boot-test | รองรับการโหลด Spring context ใน test (@SpringBootTest, MockMvc) |
| hamcrest | matcher library อีกแบบ (assertThat + is/hasItem) Spring ยังใช้ภายใน เช่น MockMvc |
| jsonassert / json-path | ตรวจเนื้อหา JSON ใน response ทีละ field |
| awaitility | รอผลลัพธ์ของงาน asynchronous ใน test โดยไม่ต้อง Thread.sleep |

## Reflection (2–3 ประโยคต่อข้อ)

1. red bar แรกพิสูจน์อะไร ที่ green bar อย่างเดียวพิสูจน์ไม่ได้

- red bar พิสูจน์ว่า test ของเราจับ bug ได้จริง แปลว่ามันถูกรันจริงและ assert จริง ถ้าเขียน test มาแล้วเขียวเลย เราไม่รู้ว่าเขียวเพราะโค้ดถูก หรือเพราะ test ไม่ได้เช็กอะไรเลย (เช่น ไม่ถูกรัน หรือ assert แบบผ่านแน่ ๆ) พอเห็นแดงก่อนแล้วแก้โค้ดจนเขียว ก็มั่นใจได้ว่าสีเขียวมาจากโค้ดที่ถูกจริง

2. ถ้าเครื่องของคุณหายวันนี้ จะกู้งานกลับมาได้จากที่ไหน

- กู้ได้จาก GitHub repo ของตัวเอง แค่ git clone ลงเครื่องใหม่ แล้วรัน ./mvnw.cmd -B verify มันจะโหลด dependency และ build ให้ตาม pom.xml เหมือนเดิม แต่ถ้ามีงานที่ยังไม่ได้ commit กับ push ก็หายไปด้วย เลยต้อง push บ่อย ๆ
